# Changelog

All notable changes to FEx are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). FEx publishes a prerelease package on every merge to `develop`, so changes accumulate under [Unreleased] until a stable release.

## [Unreleased]

### Breaking changes

- **FEx.Sqlx / FEx.EFCore**: the deprecated `System.Data.SqlClient` is gone from both packages and from FEx code; everything runs on `Microsoft.Data.SqlClient` (now 7.1.1). `SqlConnectionExtensions.LoadDatabasesAsync`, `LoadTablesAsync` and `LoadColumnsAsync` take a `Microsoft.Data.SqlClient.SqlConnection` instead of a `System.Data.SqlClient.SqlConnection`, and the `System.Data.SqlClient` overloads of `RunSql` and `RunSqlAsync` are removed (the `Microsoft.Data.SqlClient` overloads stay). `FEx.Sqlx` and `FEx.EFCore` no longer use the `System.Data.SqlClient` package directly (`FEx.EFCore` keeps a security pin for its netstandard targets, where `EFCore.BulkExtensions` 3.6.6 pulls a vulnerable `System.Data.SqlClient` 4.8.2). `SQLInstanceInfo` keeps its explicit `Encrypt=False` connection string, so FEx's own behaviour does not change; a caller who now opens a `Microsoft.Data.SqlClient` connection with its own connection string gets the `Encrypt=True` default of `Microsoft.Data.SqlClient` (since 4.0), which a server without a trusted certificate rejects. Migrate: replace `using System.Data.SqlClient;` with `using Microsoft.Data.SqlClient;` in code that calls these extensions, and for a server without a trusted certificate add `TrustServerCertificate=True` (or install a proper certificate) to that connection string rather than weakening the default ([#215](https://github.com/Flakroup/FEx/pull/215), closes [#203](https://github.com/Flakroup/FEx/issues/203)).
- **FEx.Building (coverage gate)**: an `ICoverageTarget.CoverageExclusions` entry that names one exact file now fails the gate once the reports show that file at 100% (`StaleReason.FileIsFullyCovered`, reported with line 0), so a debt list can only shrink; an exact-file entry that no report measures any more fails too (`StaleReason.FileNotMeasured`); directory entries (`prefix/`) are not judged this way. Migrate: delete the entry of any fully covered or unmeasured file from `CoverageExclusions` ([#204](https://github.com/Flakroup/FEx/pull/204), closes [#137](https://github.com/Flakroup/FEx/issues/137)).
- **FEx.MVVM.Rx.Legacy**: the package and the `FEx.MVVM.Rx.Legacy` namespace are removed; `FEx.MVVM.Rx` now multi-targets `net10.0`, `netstandard2.1` and `netstandard2.0`, so there is one copy of the ReactiveUI base classes. Migrate: replace the `FEx.MVVM.Rx.Legacy` package/project reference with `FEx.MVVM.Rx` and `using FEx.MVVM.Rx.Legacy.*` with `using FEx.MVVM.Rx.*`; `ViewModelBase.Title` now defaults to `string.Empty` instead of `null` ([#201](https://github.com/Flakroup/FEx/pull/201), closes [#96](https://github.com/Flakroup/FEx/issues/96)).
- **FEx.Sqlx / FEx.Sqlx.Abstractions**: `ISqlDbHelper` now exposes `SQLInstanceInfo` (new `ISqlInstanceInfo`, free of SMO/WMI types) and instance enumeration goes through the new `ISqlInstanceProvider` (default `SqlInstanceProvider`), so a consumer no longer references FEx.Sqlx just to read the product version or login mode. `ISqlDbHelper` gains a member (custom implementers must add it); `SQLInstanceInfo.LoginMode`, `FilestreamConfiguredLevel`, `FilestreamEffectiveLevel` and `HadrManagerStatus` now use the new `SqlLoginMode`, `SqlFileStreamLevel` and `SqlHadrManagerStatus` enums instead of the SMO ones. `SqlFileStreamLevel` and `SqlHadrManagerStatus` have an `Unknown` member for values the mirror does not know, and `LoginMode` reports `Unknown` (cached) instead of throwing when the instance is unreachable. Migrate: implement `SQLInstanceInfo` on custom `ISqlDbHelper` types, replace SMO enum comparisons with the `FEx.Sqlx.Abstractions` enums, and register `SqlInstanceProvider` as `ISqlInstanceProvider` where instances are enumerated; the static `SqlDbHelper.GetSqlInstancesAsync()` is unchanged ([#202](https://github.com/Flakroup/FEx/pull/202), closes [#97](https://github.com/Flakroup/FEx/issues/97)).
- **FEx.EFCore (SynchronizedDictionary save)**: a saved cached value no longer writes related non-owned entities. Changes made through a value to a referenced principal, to a one-to-many collection or to a dependent it is the principal of are not saved; a new principal referenced only by a cached value is not inserted (its key is written as the foreign key); clearing a reference whose foreign key is a shadow property (`doc.Owner = null`) is not written, as before, and a principal whose own key is a shadow property cannot set the foreign key. An item removed from an owned collection is now deleted. Owned items with a shadow key are matched by value, so an edited one is replaced by a new row with a new key. An unchanged value issues no UPDATE. Database-generated keys of new owned items are written back to the cached items. A shadow concurrency token has no cached value: as with `DbSet.Update`, the save expects its CLR default, so a row whose shadow token moved off the default is always a conflict. With `UseIndex`, an update of a row deleted elsewhere whose key is no longer cached is dropped without a save attempt. Migrate: save related entities through their own dictionary or context; insert a new principal before referencing it; set the explicit foreign key (or map it on the CLR type) to clear a reference; give owned items whose identity matters a CLR key and map concurrency tokens on the CLR type; stop relying on removed owned items being kept ([#199](https://github.com/Flakroup/FEx/pull/199), closes [#197](https://github.com/Flakroup/FEx/issues/197)).
- **FEx.Encryption / FEx.SecureStorage**: the cipher is now authenticated (AES-256-CBC + HMAC-SHA256, PBKDF2 keys), so a wrong key or tampered value is detected instead of decrypting to garbage, and an unreadable value is never overwritten with `null`. Values written by the old format cannot be read: an encrypted property holding one reads as `null` (reported through `OnDecryptionFailed`, the stored ciphertext is kept) and `ObfuscatedFileStorageService` files in the old format throw `FExDecryptionException` on `Get`. A passphrase is now mandatory, and the `MD5("{UserName}@{MachineName}")` default of `FExEncryption` is gone. The `FEx.SecureStorage` file fallback (`ObfuscatedFileStorageService`) is still keyed on the public `{UserName}@{MachineName}` string, now through PBKDF2, so it is obfuscation, not confidentiality. Migrate: provide `IFExEncryptionSettings.PassPhrase` (a get-only member; the `FExEncryptionSettings` class has a setter) of at least `FExEncryption.MinimumPassPhraseLength`, 8 characters, before the module initializes, or `FExEncryptionNotConfiguredException` is thrown; re-enter or re-import secrets after upgrading, or decrypt them with the previous package version first; replace `FExEncryption.PassPhrase` with `FExEncryption.Cipher`, `FileSecureStorageService` with `ObfuscatedFileStorageService`, drop uses of `StringHasher` and `EncryptionHelper` (removed), and stop passing `ref` to `DecryptFromSource`/`DecryptFromJsonSource`; on `net481`/`netstandard2.0`, and on Linux without libsecret, the file fallback is the only secure storage, so set `SecureStorageModule.FallbackCipher` (or `AllowObfuscatedFallback = false`) if the data must stay confidential ([#128](https://github.com/Flakroup/FEx/pull/128), closes [#72](https://github.com/Flakroup/FEx/issues/72), [#73](https://github.com/Flakroup/FEx/issues/73), [#74](https://github.com/Flakroup/FEx/issues/74), [#75](https://github.com/Flakroup/FEx/issues/75)).
- **FEx.Building**: secret masking is replaced by a redacting log sink, and the binary log moves. `FExBuild.SecretMask` and `FExBuild.MaskSecrets(string)` are removed; `FExBuild.OnBuildInitialized()` now replaces the global `Serilog.Log.Logger` with a redacting wrapper that owns the previous logger (new protected `InstallLogRedaction()` and `Redactor`); `ICompileTarget.GetBuildSettings(settings, solution, noRestore, verbosity)` is now `GetBuildSettings(settings, project, runtime = null, noRestore = true, verbosity = null)`; the binary log is written to `artifacts/logs/<project>[.<rid>].binlog` instead of `msbuild.binlog`. Migrate: use `SecretRedactor.Mask` and `Redactor.Redact(string)`; rename the `solution` argument to `project`, pass `runtime` instead of chaining `.WithRuntime`, and name `noRestore`/`verbosity` explicitly in overrides and positional callers; update any CI step that collects `msbuild.binlog`; an override of `OnBuildInitialized` must call `base`, and a build that assigns its own `Log.Logger` afterwards must call `InstallLogRedaction()` again, or lines logged until `OnBuildFinished` are not redacted ([#190](https://github.com/Flakroup/FEx/pull/190), closes [#55](https://github.com/Flakroup/FEx/issues/55), [#56](https://github.com/Flakroup/FEx/issues/56), [#57](https://github.com/Flakroup/FEx/issues/57)).
- **FEx.EFCore**: `PooledDbService.ValidateAndSaveChanges(Async)` and everything that saves through it (`RunTaskInDbContextAsync`, `RunActionInDbContextAsync`, `RunFuncInDbContextAsync`, `RunWithinTransaction(Async)` with `saveChanges: true`) now throw `DbUpdateConcurrencyException` when another writer changed a row this context modifies or deleted a row it modifies, or when this context deletes a row another writer changed, instead of silently letting the stale write win or re-inserting the deleted row. `SynchronizedDictionary` gains a protected `SaveChangesResolvingConflictsAsync` and corrects `Index` to the database state for a conflicting batch. Deleting a row that another writer already deleted is no longer an error (public `DbContextExtensions.ValidateAndSaveChangesAsync` detaches it and retries once). Migrate: catch `DbUpdateConcurrencyException` where a lost update matters and reload or merge; code that relied on client-wins (including deletes of rows changed elsewhere) must resolve the conflict itself ([#187](https://github.com/Flakroup/FEx/pull/187), closes [#182](https://github.com/Flakroup/FEx/issues/182)).
- **FEx.EFCore**: commit and initialization failures are no longer swallowed, and `BeginTransaction` stops retrying after 10 attempts instead of looping forever. The five-argument `ExecuteAsync` overloads gain a trailing optional `CancellationToken`, which is a binary break. Migrate: handle the exceptions that now surface from `ResilientTransaction` and `EnsureIsInitializedAsync`, and recompile code that calls the old overloads ([#163](https://github.com/Flakroup/FEx/pull/163), closes [#92](https://github.com/Flakroup/FEx/issues/92), [#93](https://github.com/Flakroup/FEx/issues/93), [#94](https://github.com/Flakroup/FEx/issues/94), [#95](https://github.com/Flakroup/FEx/issues/95)).
- **FEx.Flurlx**: `FlurlApiBase.GetResponseAsync` no longer retries or applies the resilience fallback to `POST`, `PUT`, `PATCH` and `DELETE`, which previously could re-send a write the server had already applied and replace the real error with a synthetic 503. A caller now sees the real exception. Migrate: override the new `protected virtual bool ShouldApplyResiliencePolicy(RequestMethod method)` in a client whose writes are safe to repeat; remove code that depended on the synthetic 503 for writes ([#138](https://github.com/Flakroup/FEx/pull/138)).

Migrate: raise the cap with `AddIdempotency(o => o.MaxStoredResponseBytes = ...)`; a custom `IIdempotencyStore` must persist `BodyNotStored`; a host that replays queued writes through `FEx.Offline` `HttpOutbox` must also expect that outbox to drop the entry as rejected (`HTTP 409`) for a write that did complete, because it keeps only 401, 408, 429 and 5xx, so keep over-cap responses under the cap ([#177](https://github.com/Flakroup/FEx/pull/177), closes [#109](https://github.com/Flakroup/FEx/issues/109)).

Existing plaintext files migrate on load; field-pattern consumers see no change. Reference preservation and type-name handling are not supported for these types. Migrate: no code change, but expect settings files to contain ciphertext after the next save, and drop `PreserveReferencesHandling`/`TypeNameHandling` for these types ([#177](https://github.com/Flakroup/FEx/pull/177), closes [#131](https://github.com/Flakroup/FEx/issues/131)).

### Security

- **FEx.Building**: a secret can no longer reach a build log. A repeated secret option (`--nuget-api-key A --nuget-api-key B`), a throwing getter, an environment variable and a parameters file are all redacted, as are credentials in URLs (`https://user:token@host/...`) and credential-like query values, in every line written through the global logger, provided the build calls `base.OnBuildInitialized()` and does not replace `Log.Logger` afterwards ([#190](https://github.com/Flakroup/FEx/pull/190), closes [#55](https://github.com/Flakroup/FEx/issues/55), [#57](https://github.com/Flakroup/FEx/issues/57)).
- **FEx.Encryption / FEx.SecureStorage**: `FExEncryption` values are authenticated and keyed from a mandatory passphrase through PBKDF2, so tampering is detected. The `ObfuscatedFileStorageService` fallback is also authenticated, but its key is still derived from the public user and machine names, so it gives no confidentiality against anyone who wants the data; supply `SecureStorageModule.FallbackCipher` for that ([#128](https://github.com/Flakroup/FEx/pull/128), see Breaking changes).
- **FEx.Platforms.Windows**: the ACL access check no longer splices the path and account names into a PowerShell script (an apostrophe in a directory name could run code), and `icacls` is started directly instead of through `cmd /C`, which expanded `%VAR%` in paths. Everyone is passed as `*S-1-1-0` so localized Windows works ([#162](https://github.com/Flakroup/FEx/pull/162), closes [#77](https://github.com/Flakroup/FEx/issues/77)).
- **FEx.EFCore**: `FExDbConfig.Password` is redacted in `ToString()` and no longer written by System.Text.Json or Newtonsoft.Json (it is still read) ([#177](https://github.com/Flakroup/FEx/pull/177), closes [#100](https://github.com/Flakroup/FEx/issues/100)).
- **FEx.Encryption**: settings files no longer hold plaintext for encrypted properties, see Breaking changes ([#177](https://github.com/Flakroup/FEx/pull/177), closes [#131](https://github.com/Flakroup/FEx/issues/131)).
- **FEx.WebScraping**: XPath filter values are escaped through the new public `XPathBuilderBase.Literal(string)`, so a value with an apostrophe no longer breaks or injects into the expression ([#177](https://github.com/Flakroup/FEx/pull/177), closes [#118](https://github.com/Flakroup/FEx/issues/118)).
- **FEx.Flurlx**: the Polly retry and fallback log lines mask URL userinfo, query values and fragments, so an API key in `?api_key=...` no longer lands in the application log ([#171](https://github.com/Flakroup/FEx/pull/171), closes [#107](https://github.com/Flakroup/FEx/issues/107)).
- **FEx.Telemetry.Sentry.Web**: the caller's address headers (`Cf-Connecting-Ip`, `X-Forwarded-For`, `X-Real-Ip`, `True-Client-Ip`, `Forwarded`) are removed from every event and transaction, and then the whole request is reduced to an allowlist of headers (Accept, Accept-Encoding, Accept-Language, Content-Length, Content-Type, Host, User-Agent) with the query string cleared. Setting `SendDefaultPii` keeps everything ([#142](https://github.com/Flakroup/FEx/pull/142), [#143](https://github.com/Flakroup/FEx/pull/143)).
- **FEx.Telemetry.Sentry.Web**: `sentry-trace` and `baggage` request headers are stripped before Sentry reads them, so an anonymous caller can no longer force its requests into the trace sample. Traces from an upstream service no longer continue into these hosts ([#153](https://github.com/Flakroup/FEx/pull/153)).

- **FEx.EFCore**: `SynchronizedDictionary.ConflictDetected` reports each cached change that was rejected because another writer changed the row, as a `CacheConflict<TKey, TValue>` (`FEx.EFCore.Models`) with the key, the rejected value, a detached copy of the database row (`null` when the row is gone or cannot be read) and `IsRemoval` for a rejected delete. An update is reported while the rejected instance is still the cached value for its key, a delete while the key is still not cached. Handlers run after the batch save has finished, outside the save lock: on a thread-pool thread for the buffered save pipeline, on the caller's continuation for a direct `SaveChangesResolvingConflictsAsync` call. A handler may wait on the cache or call `ReloadAsync`, and its exceptions are logged without affecting the save. The database rows of all changes a save rejected are read once, after its last attempt; when a later attempt of a direct save throws, the conflicts rejected before it are still raised. `SynchronizedDictionary.ReloadAsync(key, cancellationToken)` first waits for the cache changes the current save pipeline received before it was called (buffered or being saved; changes a pipeline replaced by `ResetAsync` + `InitializeAsync` still held may be dropped or saved late and are not waited for) and throws `ObjectDisposedException` when the dictionary is disposed while it waits, then replaces the cached value with the database row (through `IncludeInEntity`), or removes it when the row no longer exists, without saving the replacement back.
